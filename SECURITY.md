# Security Policy

## Supported Versions

This project has no tagged releases. Security fixes are applied to the latest commit on `main`.

## Reporting a Vulnerability

Report vulnerabilities privately through [GitHub Security Advisories](https://github.com/AndreaBonn/image-generator/security/advisories/new). Do not open a public issue.

Please include:

- a description of the vulnerability
- steps to reproduce
- expected and actual behavior
- the impact: what an attacker could achieve

Response timeline:

- acknowledgment within 72 hours
- fix for critical issues within 30 days
- coordinated public disclosure after the fix is released

## Threat Model

Image Generator is a single-user application for one machine. It has no authentication and no user accounts: anyone who can reach the backend port can use it. The design relies on both processes being reachable only from the local machine. The main threat considered is a web page open in the same browser that tries to send requests to the local app.

## Security Measures Implemented

- **Loopback-only binding**: the backend host setting accepts only `127.0.0.1` (`backend/app/config.py:29`), and the engine URL is rejected if its host is not `127.0.0.1` (`backend/app/config.py:38`). ComfyUI is started with `--listen 127.0.0.1` (`scripts/start.py:130`).
- **Cross-site request rejection**: every state-changing request is checked against `Sec-Fetch-Site` and `Origin`; requests sent by another site, or whose origin is not a loopback host, get a 403. The origin check also applies when the browser reports same-origin, to cover DNS rebinding (`backend/app/api/origin_guard.py:19`, registered in `backend/app/main.py:31`).
- **Upload validation**: uploads are capped at 20 MB and 4096 px per side, decoded with Pillow, limited to PNG, JPEG and WebP, and rejected on decompression-bomb errors (`backend/app/services/upload_service.py:20`). Recipes embedded in PNG files are capped at 64 KB (`backend/app/services/upload_service.py:22`) and validated with Pydantic, including prompt length, style count and seed range (`backend/app/models/upload.py:7`).
- **Path containment**: file paths read from the database are resolved and must stay inside the data directory (`backend/app/repositories/file_paths.py:6`). The engine output cleanup refuses a symlinked folder or one that resolves outside the output directory (`backend/app/repositories/output_repository.py:32`).
- **Job rate limit**: the job endpoints accept at most 600 requests per 60 seconds across the whole app, then return 429 (`backend/app/api/v1/job_limits.py:8`).
- **Verified downloads**: every model hosted on Hugging Face must declare a sha256 in `config/models.yaml` (`backend/app/repositories/catalog_repository.py:40`). Downloads are written to a staging folder, checked against that hash and only then moved into place (`backend/app/repositories/model_files.py:131`), with at most 5 redirects (`backend/app/repositories/model_files.py:17`). The installer applies the same check (`scripts/install_models.py:87`).
- **Pinned third-party code**: ComfyUI is checked out at a fixed tag (`engine/install_engine_actions.py:35`), and the SDXL style files are fetched from a fixed Fooocus commit and verified by sha256 (`config/styles.yaml`).
- **Dependency pinning**: lockfiles are committed for the backend (`backend/uv.lock`) and the frontend (`frontend/package-lock.json`).
- **Database access**: SQLAlchemy is used for all queries (`backend/app/repositories/`).

Not implemented: authentication, TLS, security headers, automated dependency scanning.

## Security Best Practices for Users

- Keep the app on `127.0.0.1`. Do not expose port 8000 or 8188 through a reverse proxy, port forwarding or a tunnel: neither the app nor ComfyUI has authentication.
- Downloaded images embed their prompt and settings in the PNG metadata. Strip the metadata before sharing an image if the prompt is private.
- Model files are executed by the engine. Add models to `config/models.yaml` only from sources you trust, and always with their sha256.

## Out of Scope

- Attacks that require local access to the machine or to the user account running the app
- Exposing the app beyond `127.0.0.1` against the instructions above
- Vulnerabilities in ComfyUI, PyTorch or the models themselves (report them upstream)
- Content generated by the models
- Denial of service through heavy legitimate use of the GPU
